# Company AI — Free Beta Deployment

## Chosen architecture

**Render Free Web Service + Neon Free PostgreSQL**.

This is the selected temporary test architecture for the Company AI beta. It keeps the application portable and avoids using Render's free PostgreSQL for the test database.

### Why this architecture
- Render runs the FastAPI application and serves the public website.
- Neon provides the PostgreSQL database separately, so the database is not tied to the Render service filesystem.
- Both services can remain on free tiers for the beta period, subject to their current usage limits.
- The project can later move to paid infrastructure without changing the core application architecture.

## Required beta-only environment variables on Render

- `DATABASE_URL` — the PostgreSQL connection string from Neon.
- `CORS_ORIGINS` — the exact Render public URL during beta.
- `TRUSTED_HOSTS` — the Render hostname (and later the production domain).
- `DEMO_ADMIN_PASSWORD` — a beta-only strong password; never reuse a real password.

`JWT_SECRET` and `PASSWORD_PEPPER` are generated by Render in `render.yaml`.

## Important test policy

Do not put real customer secrets, payment credentials, production API keys, contracts, private files, or production personal data into this beta.

The beta is for:
- multiple visitors;
- functional testing;
- Layan voice testing;
- Central AI routing testing;
- security testing;
- UI/UX testing;
- bug discovery and fixes.

## Free-tier behavior

Render Free web services can spin down after inactivity. This is acceptable for the beta and does not change the Company AI application design. The first request after inactivity may take longer while the service wakes up.

Neon Free can scale database compute to zero when idle. This is also acceptable for the beta.

## Production migration

After the beta is validated:
1. Keep the same application code and database schema.
2. Move the backend to a paid always-on service.
3. Move the database to production infrastructure with backups and appropriate retention.
4. Register the Company's permanent domain.
5. Rotate all secrets.
6. Perform a final security review before public launch.

The beta must remain separate from production data and credentials.
